# Один блок с переключением обычной и 3D-карты

Для опубликованной страницы https://visitbeloretsk.ru/map подготовлен [готовый код T123](snippets/tilda-map-switch.html).

23.10.2026 HTTP-источник страницы проверен: обычная карта находится в `.vb-t1__map` внутри `rec4164654901`, отдельный iframe Landscape — в T123 `rec5086753101`. Яндекс.Карта, её карточки, фотографии и штампы создаются существующим скриптом внутри замыкания.

## Установка

1. Оставить существующий блок обычной карты.
2. В редакторе Tilda открыть T123 с отдельным iframe 3D. Полностью заменить содержимое этого T123 кодом из `snippets/tilda-map-switch.html`. Не добавлять ещё один iframe рядом.
3. Опубликовать страницу и проверить опубликованный адрес, обновив кеш браузера.

Код добавляет две кнопки перед существующей областью карты, размещает 3D внутри неё и наследует её адаптивную высоту. По умолчанию показывается обычная карта. 3D загружается при первом переключении; последующие переключения используют тот же iframe. Старый блок T123 становится пустым и скрывается.

При показе 3D обычные элементы сохраняют размеры, но скрываются и становятся недоступны для фокуса. При возврате восстанавливаются прежние aria-hidden/inert. Нажатие «Места», «Где поставить штамп» и соответствующие hash-ссылки возвращают обычную карту. Инициализация Яндекс.Карты не дублируется.

`parentOrigin` задаётся по фактическому `location.origin`; отправляются только команды v1 в точный origin GitHub Pages. Ответы проверяются по origin, source и версии. После ready скрытый iframe получает suspend, видимый — resume/resize. WEBGL_UNAVAILABLE возвращает обычную карту и фокус на её кнопку. Реализация не перехватывает методы Яндекса и не читает содержимое чужого iframe.

## Граница этой интеграции

Это общий визуальный блок с переключением режимов. Камера и выбранный объект сохраняются отдельно в двух движках. Двусторонняя синхронизация мест, маршрутов и камеры потребует явного адаптера к существующему скрипту Яндекс.Карты: его map, markers и функции выбора сейчас приватны. Код не имитирует такую связь через поиск текста карточек и не заменяет штатные данные сайта.

В полученном HTML загрузчик Яндекса содержит `apikey=your-api-key`. Если обычная карта не загружается, в её существующем коде нужен действительный ключ API Яндекс.Карт; переключатель этот параметр не изменяет.

Изменения в личном кабинете Tilda не выполнялись. Предпросмотр 3D остаётся по текущему адресу `/preview/landscape/`; после выбора постоянного релиза путь меняется в одной строке new URL.

## Проверка кода

Chromium: 1365×1000 и 390×844, изолированная разметка реального блока страницы и тестовый iframe протокола v1. Прошли: ленивая первая загрузка, точный parentOrigin, одинаковые размеры карты и iframe (1200×700 / 334×580), доступность скрытых элементов, восстановление aria/inert, повторное использование одного iframe, resume/suspend, возврат со вкладки штампов и при WEBGL_UNAVAILABLE, возврат фокуса, скрытие пустого исходного T123. Это проверка разметки и протокола с фикстурой, не проверка живого API Яндекса или рендера WebGL в реальной Tilda. Код ещё нужно вставить и опубликовать на сайте.
