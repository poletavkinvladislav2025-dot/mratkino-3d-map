# Яндекс.Карта: одна загрузка API и восстановление фона

Изменение подготовлено к ревью на базе `bdda07d80841d7c295fd81d18e298992c3ffbd18`. Владелец 09.11.2026 разрешил публикацию после изменений и успешных проверок без повторного подтверждения. Исправление публикуется существующим workflow; рабочая главная и страница `/map` в редакторе Tilda здесь не редактируются.

## Что подтверждено

При проверке 09.11.2026 в Chromium обе опубликованные страницы открылись и фон отображался. На главной SDK подключался без API-ключа; на `/map` обнаружились два bootstrap-запроса `/2.1/`: с ключом и без него. Контрольные запросы фоновых плиток вернули 200. Сбой со скриншота в этой проверке не воспроизвёлся, поэтому отсутствие ключа или дубль не объявляется доказанной единственной причиной серых плиток.

Ранее наш `initMap()` смотрел только на `window.ymaps`. Пока чужой/Tilda-скрипт ещё загружался и глобального объекта не было, создавался второй bootstrap. Это устранено.

## Изменения

- Общая Promise загрузки SDK на документ: уже готовый API переиспользуется; существующий bootstrap в процессе загрузки ожидается, а не дублируется. Предпочитается существующее подключение с ключом. Ошибка сети или тайм-аут оставляют возможность повторить собственную загрузку.
- Явный ключ принимается через существующий `data-yandex-api-key`, также поддерживается конфигурация страницы `window.VisitBeloretskYandexConfig.apiKey`. Новая загрузка использует этот ключ. Чужой ключ не копируется в репозиторий, учётные данные не выдумываются. Диагностика `data-yandex-key` хранит только состояние configured/missing/conflict/multiple, без значения ключа. configured означает наличие ключа в выбранном подключении, не проверку лицензии или разрешённых доменов. Смена ключа уже загруженного API требует удаления старого подключения и перезагрузки страницы.
- Сохраняется совместимость со старыми страницами без ключа. Это не заменяет настройку действующего ключа владельца и его ограничений по доменам.
- Кнопка «Обновить фон карты» доступна у контролов обычной карты даже тогда, когда сервер прислал серую картинку с успешным HTTP 200.
- При обнаруженном сбое появляется сообщение, кнопки повторной загрузки и открытия 3D. При переходе в 3D сохраняется выбранный routeId и фильтр.
- Повтор загрузки фона проверен на настоящем API: `map.setType(null)` → восстановление исходного типа. Меняется только фоновый слой внутри прежнего экземпляра Map. Линии, метки, карточки, камера и выбранный маршрут не пересоздаются.
- Поддержаны явные ошибки изображения/слоя, доступные статусы сетевых ресурсов >=400 и ожидание готовности тех SDK-контейнеров, которые предоставляют публичную `ready()` Promise. Новые renderer-реализации без этого метода не получают ложный тайм-аут.

## Границы исправления

Яндекс может вернуть изображение-заглушку HTTP 200 как успешно загруженную плитку. Надёжно определить это через публичный SDK можно не во всех renderer-версиях. Поэтому не обещаем автоматическое обнаружение всех серых плиток; ручная кнопка обновления остаётся доступной.

Уже исполнившиеся сторонние/старые Tilda-скрипты нельзя безопасно выгрузить из SDK. После согласованной публикации следует оставить один T123 общей карты и убрать прежние самостоятельные инициализаторы API/карт. Наш код больше не добавляет ещё один bootstrap поверх существующего, но не перехватывает вставку скриптов другими виджетами.

Корректный ключ владельца требуется настроить в блоке Tilda через `data-yandex-api-key` и разрешить нужные домены в кабинете Яндекс.Карт. Значение не запрашивается в чате и не берётся из случайного чужого подключения. Эта настройка и удаление старых блоков на рабочем сайте здесь не выполнялись.

Итог: `npm run build` успешно; `npm run test:unit` — 23 модуля без ошибок; `TEST_PRODUCTION=1 npx playwright test tests/yandex-recovery.spec.js tests/common-map-live.spec.js` — 3/3, включая настоящий API Яндекса и ручной клик обновления. Для повторной загрузки задан ограниченный срок ожидания; кнопка явно принимает pointer events поверх фонового слоя.

Unit: ожидание существующего ключевого bootstrap, совместное использование одной Promise, повтор после ошибки, готовый SDK, отсутствие ключа, ограниченный тайм-аут. Браузер: имитация задержки старого Tilda-bootstrap без нового запроса, ошибка SDK и успешный повтор, ошибка фона с сохранением routeId/камеры, доступные кнопки на ширине 375 px, переход в настоящий 3D, настоящий Yandex SDK и переключение маршрута между режимами.

Данные, геометрия, 214 ID маршрутов, 54 места, штампы и правило расстояний в одну сторону не меняются.
