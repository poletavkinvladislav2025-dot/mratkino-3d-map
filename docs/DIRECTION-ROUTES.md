Подготовлено 01.11.2026. Новые страницы направлений не создавались. Используется прежний путь `/preview/unified/` и общий каталог `integration/route-catalog.json` для обоих движков.

## Подключение

Прямая ссылка на выбранный маршрут:

https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/unified/?routeId=rassypnaya-shushpa

Группа с вариантом по умолчанию: `?placeId=iremel`. Изолированное встраивание 3D: `?routeId=rassypnaya-shushpa&embed=1`. В нём отображаются варианты этого направления, без маршрутов остальных направлений. На общей карте остальные маршруты сохранены.

Один T123 для двух режимов (вместо прежней карты и переключателя):

```html
<script
  src="https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/unified/integration/tilda-map-block.js?v=20261101-routes"
  data-route-id="rassypnaya-shushpa"
  data-default-mode="yandex"
  defer>
</script>
```

Эквивалентный API (одна карта на странице):

```html
<div id="route-map"></div>
<script src="https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/unified/integration/route-map.js"></script>
<script>
mountRouteMap("#route-map", {
  routeId: "rassypnaya-shushpa", mode: "embedded", autoFit: true
}).then(map => {
  // map.setRoute("yalangas-a2"); // переключить маршрут без нового экземпляра
});
</script>
```

Параметры `data-place-id`, прежние `data-place`/`data-route` также работают. Старые routeId вида `yalangas/a1`, `malinovaya/three-peaks` остаются совместимыми алиасами тех же записей. В каталоге нет дублирующих линий для алиасов. Новые ID из архива не переименованы.

## Камера и состояние

Bounds вычислены из итоговой линии и значимых принятых точек, а не из полного reference-файла. До загрузки линии доступны сохранённые bounds. После загрузки контейнера маршрут вписывается с отступами под карточку, на телефоне — под нижнюю панель. Автоприближение не повторяется при каждом обновлении рельефа. Переключение варианта меняет линию, подписи, точки, полную дистанцию, рамку и URL. Назад/вперёд восстанавливают маршрут. Обычный и 3D-режимы используют один routeId и общий каталог; камера каждого движка рассчитывает рамку по одним bounds без пересылки движений по кругу.

## Что исправлено в исходных сценариях

- Рассыпная: цель Восточный бастион сохранена буквально; северная вершина и Западный бастион не подставлены вместо неё.
- Малиновая: принятый порядок Первая → Вторая → Третья. Выход в Отнурке и возврат тем же проверенным подходом к старту — разные варианты. Несуществующий отдельный маршрут «Через Нуру» не добавлен; неизвестный брод не отмечен.
- Ялангас: два принятых старта, общая цель, обе длины учитывают обратный путь.
- Иремель: варианты проходят через разные именованные тропы OSM, сверены с официальным буклетом; доказательства в `data/directions/source/iremel-variant-ways.json`. Дальние подходы с неизвестными точками остаются редакторскими.
- Зубчатки: точное начало опубликованного GPX из Тирлянского получено из файла RuTrail; оно не названо оборудованной стоянкой. Автомобильный подход пользователя сохранён отдельно. Старая точка 54.249104,58.534349 не используется.
- Кирель: исходная линия до цели сохранена один раз, полный поход рассчитан с возвращением по ней.
- Кумардак: конечная линия рассчитана от Иселгана к принятой цели по пешей сети. Исходный нисходящий файл сохранён как reference; сравнение показывает совпадение большей части нитки, отдельный подход включён в расчёт.
- Крака: около 4,56 км в одну сторону от Горной улицы к принятой цели; полный 16-километровый переход reference не используется для длины или камеры.
- Арвяк-Рязь: исходный GPX и два рассчитанных дорожных подхода — отдельные части MultiLineString. Остаточные разрывы не замкнуты прямыми, статус неполный сохранён.
- Большой Шатак: 2 дня, без блока штампа; отдельно показаны конец GPX и несовпадающий маркер вершины. Около 45 км относятся к пути до конца GPX и обратно, не к подтверждённому достижению маркера вершины.
- Вишнёвая: авторская линия извлечена из открытой карты ИдиЛесом. Проверка OSM не обнаружила пересечения Белой; линия пересекает Ятву, рядом отмечен низководный переход. Финиш автора не назван высшей точкой.
- Курташтау: расчёт пешего обхода дал большой неподтверждённый крюк; он не опубликован как готовая линия. Маршрут по действующим рельсам не нарисован.
- Малый Ямантау: автоматическая линия не достигает контрольных точек (отклонения до 3,2 км); она отклонена. Дополнительные официальные источники в этой проверке ответили 502/503.

## Данные и воспроизводимость

- `data/directions/input/` — неизменённые файлы архива владельца.
- `data/directions/routing/` — сохранённые результаты пешего профиля BRouter trekking и журнал запросов; автомобильный профиль не использовался.
- `data/directions/source/` — GPX из Тирлянского, геометрия именованных троп Иремеля, авторская линия Вишнёвой и аудит пересечения, сравнение с reference.
- `data/directions/research/*.json` — проверенные ссылки, HTTP-статусы и хеши исходных страниц. HTML/PDF-ответы остаются локальными; весь текст сайтов не перепубликуется.
- `scripts/prepare-direction-routes.py` — офлайн-сборка итоговой геометрии и метаданных (Python с shapely/pyproj). Команда: `/workspace/mratkino-gis/bin/python scripts/prepare-direction-routes.py`.
- `src/region/direction-catalog.json` — общий итоговый реестр 46 записей; `public/region/directions/routes.geojson` — итоговые линии. Общий route-catalog и файлы отображения с параллельными полосами генерируются обычной командой `npm run build`.
- Принятые координаты сохранены как `originalPoint`; `snappedPoint` и расстояние смещения хранятся отдельно. `originalStartPointId` сохраняет null исходного сценария даже при найденном независимом старте. `editorialStatus`, `buildStatus`, `geometrySource`, `sourceUrl`, `checkedAt` и `revision` сохранены.
