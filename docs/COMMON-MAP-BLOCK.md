## Исправление вставки

Полностью заменить прежний T123 с iframe/переключателем содержимым [tilda-map-current.html](snippets/tilda-map-current.html). Существующий блок `.vb-t1` с Яндекс.Картой оставить. Затем опубликовать страницу и загрузить её заново. Версия остаётся по одному пути `/preview/unified/`; параметр `v` только обновляет кэш. Нельзя держать прежний переключатель рядом: у него остаются собственные обработчики вкладок, а новый проверяет дубликаты.

Ссылка владельца с `place=waterTower&lat=...&lng=...&z=...` задаёт выбранное место и камеру. Для общей страницы лучше загрузить `/preview/unified/` без сохранённой камеры. Переключатель сам задаёт `place=all`, `embed=1` и разрешённый origin родителя. Отдельного iframe вручную добавлять не требуется.

## Что уже работает

Текущий загрузчик даёт одинаковые смысловые фильтры «Места», «Где поставить штамп», «Где купить паспорт» обоим движкам. На телефоне они представлены списком, на широком экране — кнопками. Вид и выбранное место сохраняются при переключении через существующий адаптер v1. Демонстрация в репозитории использует реальный 3D-iframe, но тестовый адаптер обычной карты. Живой API Яндекса и установка адаптера на сайте не проверены.

## Следующий этап: полное совпадение содержимого

1. Экспортировать единый публичный каталог из `PLACES`, `SOURCE_RECORDS` и паспортных связей. Схема: `id` (канонический), `sourceId/aliases` для старого Яндекса, `name`, `kind`, `coordinates`, `description`, `photos`, `address`, `sellsPassport`, `stamps`. Сейчас 52 места и 6 точек штампов внутри этого состава; 64 связи штампов сохранены. Горнолыжные линии/GPX остаются отдельными геоданными.
2. В обычном блоке Яндекса заменить встроенные массивы загрузкой этого каталога. Для новых точек использовать канонические ID; старые ID сохранять как алиасы. Пример коллизии: первая Малиновая `malinovaya` ↔ `malinovaya1`, третья `malinovaya-3` ↔ `malinovaya`. Вторая Малиновая и новые объекты должны добавляться в обе карты из одной записи. Одного переключателя для этого недостаточно: старый Яндекс не знает новых объектов автоматически.
3. Общая модель состояния: `engine`, `view`, `selectedPlaceId`, отдельная камера каждого движка. Переключение движка сохраняет фильтр и общий выбранный ID. Камеры не нужно синхронизировать каждым кадром — достаточно перехода к выбранному объекту.
4. Условие «где купить» брать из `sellsPassport`, состав доступных штампов — из записей каталога. Отказаться от определений по имени или регулярному выражению kiosk. Родитель управляет единственным рядом фильтров; внутренние дубли скрываются в embed-режиме.
5. Общие поля и шаблон карточки для обоих движков: название, фото, краткое описание, адрес/координаты, доступные штампы и переходы к местам/точкам. Общие обозначения: зелёные места, коричневые точки штампов, значок покупки паспорта. Данные обновляются один раз на GitHub.

Сначала следует подключить актуальную вставку и установить существующий адаптер по `UNIFIED-CONTROLS.md`. Для полного общего каталога потребуется переработать загрузку данных внутри обычного блока Яндекса; этот этап в текущем обновлении не реализован. Прямое редактирование существующего Tilda-блока по устаревшему HTML без проверки текущего кода не выполнялось.
