# Фильтры и единый блок Тильды · 27.10.2026

Постоянная 3D-карта: https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/unified/?place=all

Причина сообщения владельца: отдельный загрузчик не имел доступа к замыканию исходного скрипта Яндекса без ручной установки адаптера; у `setFilters` 3D намеренно не было движения камеры. Поэтому на обычной карте покупка паспорта не применялась, а в 3D менялись только видимые значки/подписи.

## Готовая установка

В редакторе Тильды **удалить или отключить старый блок обычной карты `.vb-t1` и старый T123 переключателя**. Оставить заголовок/вступление страницы и остальные блоки. Добавить один T123 с [этим коротким кодом](snippets/tilda-map-complete.html), затем опубликовать страницу и перезагрузить её. Новый блок проверяет дубликаты и сообщает о них, не пытаясь обходить старые обработчики.

```html
<script
  src="https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/unified/integration/tilda-map-block.js?v=20261027-filters"
  data-default-mode="3d"
  defer>
</script>
```

Основной код (~104 КБ) хранится на существующем GitHub Pages; лимит размера вставки Тильды к нему не применяется. Адрес карты `/preview/unified/` сохраняется. Параметр `v` сбрасывает кэш; это не другая карта. Для обычной карты при первом открытии можно заменить `3d` на `yandex`.

Блок использует API Яндекс.Карт 2.1. В проверенной среде API загрузился без ключа. Если для домена владельца требуется ключ, у того же script поддерживается `data-yandex-api-key="КЛЮЧ_ДЛЯ_ДОМЕНА"`. Ограничения ключа и права использования проверяются в кабинете Яндекса. При ошибке загрузки API доступна кнопка 3D. На живой странице Тильды блок автоматически не устанавливался.

## Поведение

* «Места»: только точки достопримечательностей; камера возвращается к Белорецку и окрестностям до Абзаково, не ко всему Уралу. Дальние места остаются доступными при перемещении карты.
* «Где поставить штамп»: 6 пунктов; камера охватывает их в городе.
* «Где купить паспорт»: 5 продающих пунктов; бесплатная штамп-станция исключена, в том числе из перелистывания карточек.
* Нажатие фильтра закрывает прежнюю карточку, сбрасывает выбранный объект и задаёт масштаб. Повторное нажатие возвращает эту группу после ручного перемещения камеры.
* Смена движка сохраняет фильтр и выбранное общее место. При отсутствии выбранного места движок показывает подходящую группу.
* Значки двух близких пунктов на центральной площади разнесены; координаты объектов сохранены.

## Единые данные и код

`scripts/prepare-tilda-block.mjs` импортирует `PLACES` из существующей 3D-карты, формирует `public/integration/map-catalog.json` и встраивает тот же каталог в `tilda-map-block.js`. Сейчас 52 записи: 46 мест и 6 пунктов, 64 штампа. Имена, короткие описания, координаты, фото, флаг покупки и связи штампов берутся из одной базы. Внешнего запроса JSON при открытии нет; версия каталога совпадает с версией блока.

Старые ID Яндекса сохранены отдельно от `canonicalId`. Первая Малиновая: `malinovaya1` → `malinovaya`; третья: `malinovaya` → `malinovaya-3`. Вторая Малиновая и исправленный центр водонапорной башни присутствуют в обеих картах. Карточки обычной карты используют прежний интерфейс владельца; 3D-модели, горнолыжные линии и GPX остаются в существующем 3D-приложении.

`src/integration/yandex-template.html` и `yandex-runtime.js` — извлечённые оформление/поведение обычной карты из ранее сохранённого исходника владельца. Удалены независимые массивы мест/штампов/описаний и фотобанк; добавлены данные из `PLACES`, встроенный адаптер и защита от запоздалого открытия карточки после смены фильтра. Это готовая замена исходного блока, не скрытая модификация живой Тильды.

В bridge добавлена явная команда `focusView {view:'places'|'stamps'|'passport'}`. Прежняя `setFilters` сохраняет поведение без перемещения камеры. Проверка origin/source, ограничение очереди и подавление событий-эхо остаются. Адаптер Яндекса v1 принимает необязательный `{focus:true}` в `setFilter`; старый вызов без options работает.

Сборка: `npm run build` автоматически генерирует блок; сгенерированные JS/JSON коммитятся вместе с изменением базы. Ручной inline-переключатель остаётся альтернативой для уже установленного старого Яндекса с адаптером, но рекомендуемая новая установка — один полный блок.

## Проверено перед публикацией

`npm run test:unit`: 54 проверки; `npm run build`: успешно. Финальный production-прогон `filter-navigation.spec.js` и `yandex-live.spec.js`: 5 сценариев прошли. Проверены 1365×900 и 390×844, смена масштаба, видимость всех 6/5 значков, закрытие карточки и отсутствие горизонтального переполнения. Обычный интерфейс дополнительно проверяется с изолированным API-стендом на точный состав маркеров; это не выдаётся за настоящий Яндекс.

Отдельный браузерный сценарий загружает **настоящий API Яндекса** через настроенный прокси, проверяет фильтры/масштаб и переход выбранной `kiosk3` из Яндекса в настоящий 3D-iframe и обратно с сохранением фильтра покупки. Два прежних сценария общего переключателя (`unified parent`, desktop/mobile) также прошли после изменения фокуса. Эмуляция Chromium; прямое редактирование Тильды и испытание физических телефонов не выполнялись.

В ходе проверки увеличены безопасные отступы 3D-камеры: южный пункт на широком экране попадал под нижнюю охранную область меток. Для UI-проверок используется ожидание обновления меток после штатной паузы камеры 140 мс, а не мгновенный снимок между состояниями.
