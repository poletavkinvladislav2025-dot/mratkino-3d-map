# Малиновая, Ялангас и расширенная сцена Мраткино

Дата проверки: 23 октября 2026 года (Москва). Развитие существующего проекта, один экземпляр MapLibre. Тестовые адреса:

- [Малиновая](https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/region/?place=malinovaya).
- [Ялангас](https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/region/?place=yalangas).
- [Мраткино](https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/region/?place=mratkino).

## Пять пеших вариантов

| Вариант | Длина линии | Возвращение |
|---|---:|---|
| Белорецк → Первая Малиновая → Белорецк | ≈ 7,9 км | Точное повторение пути подъёма |
| Отнурок → Третья Малиновая | ≈ 5,4 км в одну сторону | Кнопка показывает тот же путь в обратном направлении |
| Белорецк → Первая → Вторая → Третья → Отнурок | ≈ 12,2 км | Сквозной, финиш в Отнурке |
| Ялангас от А1 | ≈ 9,4 км в одну сторону | По той же линии |
| Ялангас от А2 | ≈ 10,4 км в одну сторону | По той же линии |

Варианты переключаются кнопками в боковой панели; на телефоне панель открывается под картой. Отображается одна выбранная линия, старт/финиш и последовательные вершины. Камера показывает весь маршрут; кнопки точек приближают отдельные вершины, «Весь маршрут» возвращает обзор. Линии драпируются MapLibre по существующему DEM. Собственный GPX/GeoJSON можно импортировать отдельно, он не заменяет встроенный вариант и не отправляется на сервер.

Это **расчётные маршруты по существующей сети OSM, требующие проверки**, а не проверенные GPS-треки. Проверена связность геометрии, не безопасность и не актуальная проходимость. Набор высоты и время не выдумываются. На линиях могут быть броды, участки без маркировки и сезонные ограничения.

## Источники и привязка

Изучены страницы `visitbeloretsk.ru/malinovaya` и доступная www-версия `www.visitbeloretsk.ru/yalangas`. Обе используют BRouter с профилем trekking; на странице Малиновой встроенные подтверждённые треки оставлены `null`, Вторая вершина помечена предварительной. Основной домен страницы Ялангаса отвечал HTTP 403, www-версия доступна. Официальная страница загрузки Большой уральской тропы просмотрена, но соответствие проверенного GPS-трека каждому из пяти вариантов и лицензия на его перераспространение не установлены; её GPX не копировались в приложение. BRouter использован для сравнения: подъём к Первой ≈ 3972 м против ≈ 3948 м собственного расчёта.

Геометрия построена алгоритмом Дейкстры по **общим узлам** дорог/троп двух ограниченных выгрузок OSM. Исключены `foot=no/private` и закрытый доступ без разрешённого пешеходного прохода, учтён `oneway:foot`. Переходов между несвязанными линиями нет. Для возврата с Первой координаты подъёма развёрнуты в точности. Исходные файлы Мраткино не менялись.

Вершины сопоставлены с именованными узлами OSM, ранее использованными в проекте. Запрошенные координаты сохранены в отчёте, географическая модель не выдаётся за геодезическую съёмку:

| Вершина | Координаты OSM, широта / долгота | Отклонение от точки задания | Последний узел тропы от вершины |
|---|---|---:|---:|
| Первая Малиновая, node/2031955355 | 54.0042186, 58.3151783 | 147,9 м | 16,5 м |
| Вторая Малиновая, node/2031955366 | 54.0080719, 58.3062014 | 0,2 м | 1,7 м |
| Третья Малиновая, node/763490278 | 54.0205484, 58.2915922 | 67,4 м | 5,0 м |
| Ялангас, node/743130758 | 54.1278441, 58.3185200 | 36,8 м | 5,4 м |

Начальные точки сохранены из задания. Привязка к ближайшему узлу связной сети: Белорецк 7,8 м, Отнурок 4,8 м, А1 4,6 м, А2 7,6 м. Эти зазоры не соединяются вымышленными отрезками. Маркеры показывают заданные старты и уточнённые вершины, линия — доступную исходную тропу. Для точного подхода к вершинам нужна полевая проверка последних метров.

`public/region/hiking/{malinovaya,yalangas}/routes.geojson` — повторно используемые линии и точки. `route-audit.json` содержит исходные узлы, последовательность рёбер, ID и теги OSM, привязки, SHA-256 выгрузок. Ссылка на него есть в карточке маршрута. Лицензия исходной сети и её производных — ODbL 1.0; атрибуция OSM сохранена. `data/hiking/source-research.json` содержит проверенные ссылки, даты, статусы и ограничения источников.

## Локальная природная сцена

По кнопке «Оживить карту» загружается общий ленивый Three.js и индекс только выбранной горы. Дальше — ячейки 500×500 м около камеры: до четырёх на компьютере и двух на телефоне. За один раз отрисовываются до 2400 / 700 деревьев, на масштабе ниже 14,2 объекты скрываются и ячейки освобождаются. Первая активация из общего вида приближает выбранную вершину. Нет анимации туристов и постоянного цикла кадров.

Зона подготовки — 250 м с каждой стороны реальной линии и 500 м около вершин Малиновой / 700 м около вершины Ялангаса. Полные массивы района в клиент не загружаются. Кандидаты деревьев находятся только внутри лесных полигонов; исключены нанесённые дороги/тропы с отступом 5 м, открытые скалы, осыпи, поляны, вода, кустарник и населённые участки. Сложные неполные лесные отношения OSM не дорисовывались: использованы также готовые маски `landcover/wood` нескольких локальных тайлов OpenFreeMap z13, обрезанные зоной маршрута; URL и SHA-256 сохранены в `forest-sources.json`. Эти маски обобщены картографическим источником, фактическая граница леса требует уточнения.

Отрисовываются процедурные хвойные деревья высотой 16–30 м с вариациями кроны; основания привязаны к текущему DEM. Скальные участки/осыпи/поляны выделяются по исходным полигонам OSM, обрывы — по исходным линиям, без придуманной объёмной геометрии. Цвета поверхности находятся под настоящим hillshade; направление освещения деревьев согласовано с ним. Тяжёлых текстур, фотографий и моделей нет. При выключении режима или смене локации очищаются запросы, ячейки, наблюдатели и GPU-ресурсы.

Для Малиновой подготовлены 54 ячейки и 27 702 кандидатов деревьев, для Ялангаса — 83 и 41 132. Это общий запас для перемещения камеры, не число одновременно загружаемых объектов. Ячейка занимает до ≈ 50 КБ JSON до HTTP-сжатия; в конкретном ракурсе загружаются только ближайшие разрешённые ячейки. Общий Three.js ≈ 482 КБ до сжатия подгружается один раз для любых сцен; модуль природы ≈ 5,7 КБ. Базовая карта и маршруты работают без этих модулей.

## Точный рельеф скал

Изучены Copernicus DEM и PGC (ArcticDEM / EarthDEM). Copernicus GLO-30 — глобальные 30 м; существование EEA-10 не подтверждает доступность 10-метровой съёмки Белорецка. Открытый STAC PGC перечисляет EarthDEM 2 м и ArcticDEM, но запросы по площадям Первой Малиновой и Ялангаса вернули 0 объектов на дату проверки; результаты сохранены в `data/hiking/pgc-*-search.json`. Отдельная страница EarthDEM ответила 403. Таким образом, пригодная лицензированная высокоточная модель этих скал не установлена; это не утверждение об отсутствии съёмки вообще.

Рельеф остаётся Mapterhorn с исходной детализацией до z12 и существующими открытыми DEM. Приближение камеры не создаёт измеренные скальные детали. Фотограмметрия, текстурированные модели скал и художественная реконструкция не добавлялись. Для точной геометрии потребуется локальная съёмка/модель с понятными правами и высотной привязкой.

## Мраткино

На компьютере до 60 персонажей на каждой из шести трасс — **360 всего, включая 120 сноубордистов**; на узком экране — 24 на трассу, 144 всего, включая 48 сноубордистов. Это ровно ×3 относительно предыдущих 120 / 48. Естественный масштаб фигур сохранён.

Ширина берётся из поперечных пересечений соответствующих полигонов, с отступом 2,5 м от края, с учётом отверстий и сужений. Исчез прежний предел ±14 м и ограничение меньшей симметричной стороной. Полосы и дуги распределены по ширине; скорость пересчитывается с учётом длины дуги. Привязка: С2 — way/933845738, С3 — way/933845736, Ю1 — way/933845746 с общим нижним участком way/933845745, Ю2 — way/933845745, Ю3 — way/933845742, Ю4 — way/933845741. Это соответствие геометрии исходника, не независимая проверка курортом.

Пространственные резервации удерживают расстояние 2,8 м между фигурами, включая сливающиеся трассы; догоняющий ждёт в предыдущей безопасной позиции. Не отрисовываются позиции за пределами полигона, в нанесённых зданиях, возле станций и внутри полигона закрытой С1 (relation/12615529). С1 не используется ни как маршрут, ни как доступная ширина соседнего спуска. Персонаж не создаётся на участке без исходного полигона. Это иллюстрация, без обещания физической симуляции реального поведения людей.

## Воспроизведение и публикация

```sh
# С установленными requirements-gis.txt; исходные выгрузки переиспользуются.
python scripts/prepare-hiking-data.py
# Только для явного обновления ограниченных исходных выгрузок:
python scripts/prepare-hiking-data.py --download
npm run test:unit
python -m unittest discover -s tests -p 'test_hiking_geo.py'
npm run build
TEST_PRODUCTION=1 npx playwright test tests/hiking.spec.js tests/rider-crowd.spec.js tests/recovery.spec.js
```

Скрипт скачивает только отсутствующие локальные исходные тайлы. В опубликованной карте расчётов через BRouter и обращений к OSM API нет: подготовленные GeoJSON и ячейки обслуживаются GitHub Pages. Отказы необязательного модуля не подменяют маршруты прямыми линиями и не удаляют базовую карту.

Публикация — существующий ручной workflow из `main` с `preview_ref=feature/beloretsk-region`. Корень GitHub Pages сохраняет закреплённую сборку `af1a594`; новая версия размещается в `/preview/region/`. Действующие страницы Tilda не редактируются. Физический смартфон в облачной среде недоступен: мобильные проверки проверяют интерфейс, лимиты и жизненный цикл сцены, а не гарантированную частоту кадров на конкретном устройстве.
