# Riders and lift animation at every mapped downhill resort

The catalogued resorts now enter the existing opt-in ResortScene lifecycle, not only the Mratkino/Abzakovo scenes. Active contexts combine nearby native areas and the winter catalog. Only one nearby catalog scene is retained. Rodeo keeps its dedicated freestyle scene and now also gets animation on its mapped lift.

Both skiers and snowboarders use the existing instanced body/equipment models and downhill rider physics. Generic route scenes use source ski lines and a conservative illustrative ±3 m carving corridor; this is not a surveyed piste boundary. No riders are placed on nordic routes or source-marked closed/restricted features. Mratkino S1 remains closed and excluded by its existing profile.

Per-resort rider budget: up to 240 desktop or 96 mobile, also limited to 36/14 per source segment. Counts vary with the mapped route geometry and visibility. Animation is active in close 3D views when «Оживить карту» is enabled, pauses during camera motion/visibility suspension and disposes when leaving the active context. Terrain is sampled during refresh and interpolated for generic rider/vehicle animation, without per-frame terrain queries.

Lift types follow mapped aerialway tags: open chairs, gondola/cable-car cabins, platter/J/T drag lifts, rope tows and conveyor belts. Capacities use source occupancy where present; passenger detail and vehicle instance counts are bounded. Gondolas use a closed cabin model, T-bars a horizontal crossbar, ropes omit the platter stem and conveyors use moving flat pads. These are illustrative animations, not real-time operational status.

Ak Yort previously had only a point. Added exact OSM ways 61740147 and 1271090628 (downhill) and 61740159 and 1271090629 (drag lifts). Nearby unrelated ski areas, jumps and the public cable car were excluded. The existing point is retained; its source node is the named sports-center bus stop, while the imported lines have their own bounds. Source selection, hashes and coordinates are recorded in `data/landscape/ak-yort-life-provenance.json` and the retained OSM extract. `scripts/extend-ak-yort-catalog.py` reproduces the import. The new lines feed both the ordinary map and 3D through the existing shared route catalog.

Validation: unit suite and production build passed. Pure data checks cover every catalogued downhill resort, both equipment types, device instance budgets, closed/restricted exclusions and all supported source lift types. Real-tile Chromium checks passed on Zavyaliha, Sunny Valley, Ak Yort and Bannoye: visible people, nonempty terrain-following lift loops, gondola/conveyor classification, progressing scene time, no terrain queries from per-frame generic rider/vehicle updates, and disposal/recreation on parent suspension. Existing Mratkino/Abzakovo rider and lift data/motion unit checks remain green. Mobile counts were checked as data budgets; physical mobile hardware was not tested.
