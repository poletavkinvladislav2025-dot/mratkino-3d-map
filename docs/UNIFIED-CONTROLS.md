# Независимые режим, фильтр и оживление

Ветка `feature/unified-map-controls` создана от проверенного `b56e7a9`. Перед работой сверены GitHub refs и HTTP build-info: предыдущая публикация `134eb65`; разница до `b56e7a9` — только два файла итогового отчёта. Прежняя ветка не принята за актуальную без проверки.

Новый отдельный предпросмотр: https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/unified/?place=all

Демонстрация родителя: https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/unified/integration/unified-demo.html

Демонстрация содержит настоящий iframe 3D и **тестовый адаптер обычной карты без API Яндекса**. Это не живая Tilda/Яндекс.Карта. При новом запросе https://visitbeloretsk.ru/map получен HTTP 403; для точечных вставок использован ранее прочитанный в этой сессии исходник страницы.

## Что устанавливать в Tilda

Существующий блок Яндекс.Карты `rec4164654901` оставить. Полностью заменить только T123 `rec5086753101`, где находится прежний iframe или переключатель. После публикации перезагрузить страницу, чтобы старые анонимные обработчики show(false) не оставались в памяти.

Полный вставляемый код с загрузкой опубликованного переключателя:

```html
<script
  src="https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/unified/integration/tilda-map-switch.js"
  data-map-url="https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/preview/unified/"
  data-default-mode="yandex"
  defer>
</script>
```

Для 3D по умолчанию заменить только `data-default-mode="yandex"` на `data-default-mode="3d"`. `#map-stamps` задаёт фильтр штампов, `#map` — мест, сохраняя текущий движок. [Полный автономный вариант HTML с тем же JS внутри](snippets/tilda-map-switch.html) доступен для вставки без внешнего script src. Оба варианта взаимоисключающие: устанавливать один.

Код добавляет один общий ряд режима/фильтра и скрывает старый ряд `.vb-t1__tabs`. На телефоне фильтр превращается в select; нет трёх рядов одинаковых кнопок. `embed=1` убирает бренд и три общих фильтра внутри iframe; поиск, оживление и дополнительные категории остаются. Без embed бренд и самостоятельные фильтры доступны. Родитель не читает DOM чужого iframe или текст карточек.

При отсутствии адаптера обычные «Места»/«Где поставить штамп» вызывают существующие обработчики Яндекса. Фильтр продажи паспорта и передача выбранного ID на стороне Яндекса требуют адаптера ниже. Без него код сообщает об ограничении; полной синхронизации не обещает.

## Точечные вставки в существующий скрипт Яндекса

Это изменения **внутри** существующего `(function(){ ... })();`, где доступны `map`, `markers`, `locations`, `stampPoints`, `selectedIdx`, `currentTab`, `switchTab`, `navToLoc`, `navToKiosk`. Никакого `window.map` не требуется.

1. Непосредственно перед последним вызовом `initMap();` вставить содержимое [yandex-adapter.js](snippets/yandex-adapter.js). Это обычный JS, без нового `<script>` внутри уже открытого script.
2. В начале существующей `function switchTab(name,fit,autoSel){` добавить:

```js
vbPassportOnly=false;
```

3. В конце этой же `switchTab`, после строки `if(autoSel!==false&&vis.length>0)selectMarkerByIndex(vis[0]);`, добавить:

```js
vbYandexNotify();
```

4. В `selectMarkerByIndex(idx)` непосредственно после `selectedIdx=idx;` добавить:

```js
vbYandexNotify();
```

5. В конце `createMap()`, после `mapLoader.classList.add('vb-t1__map-loader--hidden');`, добавить:

```js
window.dispatchEvent(new Event('vb-yandex-ready'));
```

Адаптер экспортирует только ограниченный API `VisitBeloretskYandex.version/getState/hasPlace/setFilter/openPlace`. Получает исходные ID, а не имена карточек. Программные операции подавляют обратные события; одинаковые пользовательские состояния не дублируются. На обычной карте фильтр покупки скрывает stampStation, оставляет пять киосков. Переходы к объекту выполняются через прежние nav-функции; краткое ожидание завершения перехода не теряет последний запрос.

Первая Малиновая: 3D `malinovaya` ↔ исходный `malinovaya1`; Третья: 3D `malinovaya-3` ↔ исходный `malinovaya`. Остальные различающиеся ID сопоставлены явно. Только объекты, известные `hasPlace`, передаются в Яндекс. Новые курорты, которых там нет, автоматически не создаются. Камеры двух движков не синхронизируются непрерывно: передаётся выбранный общий объект, а при отсутствии общего объекта сохраняется собственная камера движка.

## Протокол setFilters v1

```js
{
  type: 'vb3d.command', version: 1, id: 'site-filter-1',
  command: 'setFilters', payload: {view: 'stamps'}
}
```

`view`: `all`, `places`, `stamps`, `passport`. Дополнительные поля `ski/nordic/hiking` — boolean. Вместо view допустимы частичные boolean `interesting/stamps/passport`; одновременно с view они отклоняются как неоднозначные. Пустые payload, неизвестные поля/значения и строки вместо boolean отклоняются.

Команда проходит прежнюю очередь готовности, проверку origin/source, дедупликацию ID и ограничение очереди. `ready` и `commandResult` содержат `filters`. Пользовательское изменение отправляет `filtersChanged {filters:{ski,nordic,hiking,interesting,stamps,passport,view}}`. Команда родителя подтверждается через commandResult и не порождает filtersChanged — поэтому эхо не запускает следующий обмен. Старые команды сохранены. Родитель хранит последний выбранный фильтр до загрузки JS iframe и применяет его после ready; уже поступившие приложению команды стоят в его собственной очереди.

## Карточки, ландшафт и сохранность данных

Новый объект открывается с прокруткой сверху; обновление того же ключа не перестраивает карточку. Камера учитывает место панели, а заголовок/закрытие доступны. На телефоне описание доступно в раскрытой нижней карточке. Одна фотография и навигация заменяют длинную колонку. Отдельный dialog показывает крупное изображение, перелистывание, известные подписи/авторов и закрытие Esc. Файлы размером до 2×2, data-пиксели и ошибки загрузки скрываются. Все исходные ссылки и записи фотографий сохранены в данных.

Условия штампов выводятся один раз, список сворачивается как «Штампы в этой точке · N». Служебное имя Краки исправлено только в displayName; история координат сохранена. Историческая точка сообщает «Объект утрачен»; условность этнопарка объясняется один раз в «О карте». Ограничения посещения сохранены.

Легенда использует queryRenderedFeatures по действительно отображённым линиям: горнолыжная сложность — только для downhill, отдельные подписи для пеших и беговых маршрутов. Близость к курорту не включает её сама по себе. Цвета подтверждённых трасс не менялись.

Добавлены только базовые имена city/town/village/hamlet и названия улиц transportation_name; POI не включены. Реальный городской тайл и шрифт Noto Sans Regular проверены HTTP 200. Вода и DEM не перемещались. Умеренно усилены лес/открытые территории, вода/берег и иерархия дорог. Городской экструзии нет.

У деревьев четыре общие формы крон, более плотные пропорции, менее тонкие стволы, стабильные исходные позиции. Количество деревьев и ячеек, Worker и маски воды/дорог/трасс/загона сохранены. Дополнительная общая форма повышает число пакетных вызовов на один, а не добавляет draw call на дерево. Прежний бюджет 12000/3600 деревьев и 24/10 МБ собственного слоя сохранён; это не предел памяти всего браузера и не обещание FPS.

## Проверка и ограничения

Production-сборка прошла. Все 10 файлов Node unit-тестов прошли: прежние данные/геометрия/37 точек/64 связи и новые строгие фильтры, легенда и адаптер замыкания. Исходные JSON мест, координаты и ссылки фотографий не менялись; в экспортированном GeoJSON изменено только отображаемое имя Краки.

В Chromium с настоящим WebGL через SwiftShader и настоящими тайлами/фотографиями через TLS-проверяющий прокси выполнены все 6 сценариев tests/unified.spec.js в нескольких целевых прогонах:

| Сценарий | Результат |
|---|---|
| Родитель на компьютере и телефоне | Фильтры, #map-stamps и #map сохраняют движок; фильтр и общий исходный ID передаются; кнопки соответствуют режиму; горизонтального переполнения нет |
| Оживление при смене движка | Предпочтение остаётся включённым, скрытый iframe получает suspend, возвращённый — resume |
| Очередь до готовности | В настоящий iframe отправлена команда, пока manifest намеренно ещё не отдан; она попала в очередь и подтверждена после загрузки |
| Защита от эха | Команда фильтра подтверждается без filtersChanged; пользовательский фильтр выдаёт одно событие; поток сообщений после действий не растёт циклически |
| Карточки/галерея | Новый объект — scrollTop 0; sync того же объекта сохраняет чтение; реальные фото киоска и башни открываются крупно, 2 фото перелистываются, Esc закрывает только просмотрщик |
| Легенда/камера | Городской киоск без горнолыжных линий — без легенды сложности; при обзоре Мраткино показаны категории; выбранная точка вне мобильной панели; кнопки названы «Вид сверху / Наклонный вид» |
| Обзор и этнопарк | Реальные снимки леса/трасс и сцены с 20 оленями; движение включается, бюджет деревьев не расширен |

Это не один полный прогон всех старых браузерных тестов. Первую проверку фото повторили после перезапуска устаревшего локального прокси, который не допускал Tilda CDN; реальный CDN отдельно подтвердил HTTP 200 и 1672×941. Исправлены селектор теста с двумя h3 и ожидание готовности: для настоящей проверки очереди задержан manifest, а не независимый векторный источник.
