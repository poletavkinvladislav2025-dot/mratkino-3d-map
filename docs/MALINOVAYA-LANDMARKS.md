# Малиновые и совмещение башни — 26.10.2026

Добавлена одна новая точка `malinovaya-2` — «Вторая Малиновая», `[58.306933, 54.007729]` (долгота, широта), по сообщению владельца. Первую (`malinovaya`) и Третью (`malinovaya-3`) сохранили отдельно, включая прежние паспортные связи и исходные координаты. В каталоге теперь 52 места, плюс город. Точка доступна через поиск, список и стандартное открытие места. В карточке короткое описание; новый пеший маршрут по прямой не строился. Существующие маршруты массива доступны рядом со всеми тремя вершинами.

Для Первой Малиновой использованы полная линия обрыва [OSM way/616057078](https://www.openstreetmap.org/way/616057078) и полигон обнажённой породы [OSM way/616057075](https://www.openstreetmap.org/way/616057075), полученные через OSM API HTTP 200. Сопоставление с World Imagery (z17, 4×4 тайла) показало, что линия идёт вдоль видимого светлого гребня; плановые координаты OSM сохранены. Источники и параметры снимка — `data/landmarks/malinovaya-provenance.json`. Спутниковые изображения в сборку не включаются. Геометрия — `src/landscape/malinovaya-rocks.json`, ODbL, действующая атрибуция OSM сохранена.

Статичные скалы добавлены в существующую общую Three.js-сцену: неровные многогранные столбы, серые слои, трещины, отдельные камни у подножия. Геометрия опирается на DEM; высоты и детали являются художественным приближением по фотографиям владельца, а не фотограмметрией. Один объединённый меш, без внешних 3D-файлов и текстур. Перестроение только при изменении рельефа, без вычислений каждый кадр. Ресурсы освобождаются при удалении сцены/скрытии. Лес не заполняет исходный полигон скал. Плоское обозначение породы также видно при приближении. Слои «Места» и «Туристические маршруты» управляют скалами. При выборе Первой камера показывает весь гребень, «Рассмотреть скалы» приближает центральную часть. Общий стартовый обзор не меняется.

Башня перенесена в центр круглого здания [OSM way/510740710](https://www.openstreetmap.org/way/510740710): `[58.40492627, 53.97033042]`, около 11 м от прежней точки. Это исправление прямо запрошено владельцем по скриншоту. Обновлены и модель, и маркер, и камера. Прежние значения `53.970428, 58.404897` остаются в исходных полях записи и CSV; новые координаты записаны отдельно как `ownerCoordinates`, с источником и причиной коррекции. Геометрия контура и прежняя точка — `data/landmarks/tower-alignment.json`. Пока видна подробная модель, исходная маленькая экструзия внутри точного участка контура скрывается; соседние здания сохраняются. При скрытии подробной модели исходный объём возвращается.

Проверки: весь модульный набор, production build; desktop/mobile браузерные сценарии на реальных тайлах — показ скал и близкий ракурс, скрытие/возврат фильтром, поиск Второй Малиновой, географические координаты башни, фильтр серого дубликата и его возврат. Скриншоты в `renders/malinovaya-rocks-*.png`, `renders/tower-aligned-*.png`. В функциональном тесте 3D-лес отключён для скорости программного GPU в облаке; настройка леса в продукте не менялась.

Публикация только по действующему пути `/preview/unified/` через `unified.yml`, вставка Тильды и старые адреса сохраняются.

В процессе проверки исправлена гонка DEM: таймер пакетного обновления мог отработать до фактической отрисовки высот. Теперь после содержимого DEM выполняется одно завершающее обновление на `idle`; ожидание переживает движение камеры, постоянного цикла перерисовки нет. Регрессионная модульная проверка покрывает оба случая. Модели не создаются на временной нулевой высоте, пока DEM загружается.

Итоговая проверка: все 17 модульных файлов прошли, production build успешен. Оба окончательных браузерных сценария (390×844 и 1365×900) прошли после исправления DEM: 2/2. На горизонтальном тестовом основании скалы содержат 66 колонн вдоль 364 м исходной линии, 8256 треугольников, один draw call. Высоты форм в продукте адаптируются к DEM.
