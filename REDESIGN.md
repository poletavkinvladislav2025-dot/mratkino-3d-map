# Редизайн карты Мраткино — 22 октября 2026

## Сохранение и сравнение

Исходная рабочая карта сохранена коммитом `c049689` и меткой
`checkpoint/before-redesign-2026-10-22`. Новая работа — ветка

после изменений — `renders/live-{south,north,overview,mobile}.png`.

## Что изменено

- Компактная шапка, сегментный выбор склонов, плитки трасс, карточки и отдельный
  список четырёх подъёмников. Инструменты находятся справа, карточки — рядом с
  картой, на телефоне — в раскрывающейся панели под ней.
- Светотень стала контрастнее. Площадные объекты спусков больше не заливаются
  непрозрачным белым и не обводятся постоянно: этот слой подчёркивает реальные
  полигоны, вместо резкого вырезания снега из леса.
- Лес отображается полупрозрачной мягкой растровой маской по исходным OSM-
  полигонам: только внутреннее сглаживание границ, без добавления леса снаружи.
  Исходные GeoJSON не изменены. Маска 2048×2048, около 243 КБ, одна текстура.
  Скрипт воспроизведения: `python scripts/prepare_winter_forest.py`.
- Подписи проходят проверку столкновений на каждом кадре: выбранная трасса
  имеет приоритет, затем вершина. Скрытая подпись остаётся доступна в каталоге.
- Общий вид показывает каталог обоих склонов. Выбор другого вида сбрасывает
  старую карточку. Камеры учитывают свободное место у панели и инструментов.
- Исправлена ошибка обращения к неопределённому `e` при долгой загрузке DEM.
  Резервный вид может уступить место успешно догрузившейся живой карте.
- Библиотека MapLibre — отдельная npm-зависимость и отдельный production-чанк;
  собственные DEM, OSM и worker размещаются вместе с картой без внешнего API.

## Достоверность и ограничения

Copernicus GLO-30 — исходная модель поверхности с шагом около 30 м, а не
высокоточная съёмка склона. Переподготовка PNG-тайлов не увеличивает реальное
разрешение. Локальная гранёность и влияние крон деревьев в DSM могут оставаться.
Геометрия DEM не усиливается: exaggeration=1. Зимняя палитра и светотень —
оформление, не сведения о текущем снеге.

Не изменены GeoJSON трасс, подъёмников, леса, станций и контуров; исходные DEM-
тайлы также сохранены. Ю5 по-прежнему без геометрии; конфликт Ю3/ref=Ю2 сохранён.
Сложность и паспортные длина/перепад не придуманы. Направление спуска не нанесено:
порядок вершин OSM не является подтверждением разрешённого направления.
Состояние трасс и подъёмников в реальном времени не заявляется.

## Публикация и Tilda

Workflow `.github/workflows/pages.yml` собирает карту при обновлении `main`:
`npm ci` → проверки логики → production build → GitHub Pages.
Артефакт содержит подготовленные данные: Python/GIS/Blender на сервере не нужны.

Автоматическое включение Pages через GitHub API отклонено: **403 Resource not
accessible by integration**. Это ограничение разрешений GitHub-интеграции,
хотя запись кода в репозиторий доступна. Владелец должен один раз открыть:

https://github.com/poletavkinvladislav2025-dot/mratkino-3d-map/settings/pages

и выбрать **Build and deployment → Source → GitHub Actions**. Затем запустить
workflow **Publish Mratkino map** во вкладке Actions (Run workflow, main).
Ожидаемый адрес после успешной публикации:
https://poletavkinvladislav2025-dot.github.io/mratkino-3d-map/

До успешного workflow этот адрес нельзя считать опубликованной новой картой.
`public/tilda-embed.html` содержит короткий iframe для T123. В действующий сайт
Tilda изменения не отправлялись. После встраивания обновления `main` будут
появляться в карте без повторного копирования исходного кода в Tilda.

Альтернативный хостинг: содержимое `dist/` или `deliverables/mratkino-web.zip`
можно разместить на любом статическом HTTPS-хостинге и заменить `src` iframe.
Карточки на телефоне раскрываются внутри прокручиваемого iframe; высота
адаптирована, полноэкранный режим разрешён. Финальная проверка в редакторе
Tilda и на физических телефонах потребует открытия тестовой страницы владельцем.

## Сравнение светотени

В одной камере проверены `standard`, `basic`, `igor` при одинаковой силе 0.75.
Изображения: `renders/style-{standard,basic,igor}.png`. Выбран `igor`: тени
мягче, чем у `basic`, линии на лесном склоне читаются лучше. Сильная legacy-
отмывка подчёркивала мелкую гранёность DSM. Разрешение и геометрия DEM одинаковы.

В Chromium/SwiftShader измерен интервал 30 принудительно отрисованных кадров:
медианы standard ≈883 мс, basic ≈817 мс, igor ≈850 мс. Это программная
отрисовка облачной среды, а не FPS физического телефона; существенного выигрыша
между методами этот опыт не доказывает. Дополнительных DEM-тайлов метод не
требует. Текстура леса добавляет около 243 КБ; canvas ограничен 1.5×, на
малых экранах рендерится меньше пикселей. Реальные мобильные GPU ещё не измерены.

## Проверки данных

Шесть GIS-тестов проверяют Terrarium, высоту реальной вершины, исходные OSM,
конфликт Ю3 и отсутствие добавленного леса за пределами масок. Два JS-теста
проверяют противоположные ракурсы склонов и запрет выдачи OSM-сложности за
подтверждённую категорию. `git diff` относительно checkpoint подтверждает, что
исходные GeoJSON и DEM-тайлы не изменены.
