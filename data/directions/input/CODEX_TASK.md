# Задание Codex: единый каталог маршрутов Visit Beloretsk и карта с приближением к выбранному маршруту

Реализуй работу в текущем проекте карты Visit Beloretsk. Сначала изучи код и AGENTS.md. Используй существующую карту, движок, дизайн и источник данных; не создавай второй несвязанный экземпляр каталога. Изменения должны быть конкретными и проверенными.

## Входные файлы

- routes.json — все принятые координаты,  постоянные ID, варианты и статус полноты. Неизвестные точки заданы null, а не выдуманы.
- source-tracks.geojson — пять реально скачанных исходных линий, в порядке [долгота, широта]. Это reference-геометрия: она не всегда совпадает со сценарием страницы.
- track-audit.json — независимая проверка длины и крайних точек исходных файлов.
- route-scenarios.md — подробные описания, решения пользователя, расхождения и источники.

## Результат

На общей карте уже существуют маршруты с постоянными routeId и группами placeId. Страница горы подключает тот же маршрут по ID, без копирования геометрии. При открытии страницы Рассыпной показывается её пеший путь из Шушпы к Восточному бастиону, с автоматическим масштабом по всей линии, а не весь Белорецкий район. Так же работают остальные направления.

## Сначала построй корректные линии

1. Импортируй все записи. Для неполных маршрутов сохрани редакторский статус, не называй их готовыми и не рисуй фиктивные линии.
2. Для маршрутов с известными точками найди исходный GPX в sourceUrl или рассчитай пеший путь по дорогам/тропам. Используй пеший профиль доступного движка. Автомобильный профиль недопустим для пешей части. Результат обозначай как исходный GPX либо расчёт по карте — это разные типы источника.
3. Проверь нитку по статье: переправы, развилки, подход к нужной вершине. Если роутер не знает тропу, показывай точки и статус, а не прямую линию. Не вычисляй длину похода как расстояние по прямой. Не проводи трек по действующим железнодорожным путям и мостам.
4. Для Верхней и Нижней троп Иремеля нужны разные реальные геометрии; одинаковые старт и цель сами по себе не определяют вариант. Получи треки самостоятельно по источникам. Не создавай один и тот же путь под двумя названиями.
5. Арвяк-Рязь: исходное кольцо начинается в 79 м от пользовательского старта; разрыв конца и начала 39 м. Сохрани пользовательский маркер, уточни подход; не замыкай пробел прямой автоматически.
6. Кирель: файл только до вершины, 3.213 км. Обратный путь тем же маршрутом. На карте можно одну линию с подписью «туда и обратно», расстояние полного похода — удвоенное после финального пересчёта. Не рисуй искусственный круг.
7. Кумардак: исходный GPX идёт от вершины вниз, заканчивается южнее Иселгана. Разверни направление, найди корректное соединение от шале. Исходные 11.214 км не являются длиной всего похода от шале туда-обратно.
8. Крака: исходные 16.170 км — полный переход Азнагулово — Шигаево. Нужен короткий участок от Горной улицы до пользовательской цели и возврат. Полный reference-трек не должен влиять на масштаб страницы Краки.
9. Большой Шатак: оставь 2 дня, без блока штампа. Файл 22.638 км в одну сторону, около 45 км туда-обратно. Конец файла и маркер Яндекса различаются на 459 м. Исследуй отличие; до разрешения показывай отдельные маркеры с точными названиями, без придуманного соединения и утверждения, что конец GPX — точная вершина.
10. Рассыпная: согласованная цель — Восточный бастион. Северная высшая точка и Западный бастион — отдельные ориентиры, не подменяй ими пользовательскую цель.
11. Все три Малиновые: обязательный порядок Первая → Вторая → Третья. Вариант с финишем в Отнурке отдельно от возврата к старту в Белорецке. «Через Нуру» не отдельный маршрут. Координаты самого брода неизвестны: не ставь случайный маркер реки.
12. Зубчатки: три варианта; пользовательский автомобильный подъезд 54.245063,58.546698. Для низкой машины текст предлагает пеший старт из Тирлянского. Найди точную стоянку самостоятельно; центр посёлка не подставляй вместо неё. Старую точку 54.249104,58.534349 не используй как текущий согласованный старт.
13. Для маршрутов с null-start/null-goal продолжи поиск по источникам; не проси владельца найти общедоступные координаты. Если данных недостаточно, оставь запись в редакторском каталоге со статусом и причиной. Не публикуй непроверенный маршрут как готовый.

## Связь карты и страниц

Согласуй интерфейс с текущим проектом. Если аналога ещё нет, поддержи:

- /map?routeId=rassypnaya-shushpa — выбран ровно этот маршрут; после загрузки линии карта вписывает её целиком.
- /map?placeId=rassypnaya — группа направления, выбран её defaultRouteId.
- /map?routeId=rassypnaya-shushpa&embed=1 — компактное встраивание той же карты для Tilda.

Это предлагаемые параметры для реализации, а не утверждение, что они уже работают. Используй существующий домен/путь проекта. Не переименовывай routeId после подключения страниц.

Предусмотри удобный вызов из кода страницы: mountRouteMap(container, {routeId, mode:'embedded', autoFit:true}) либо эквивалент на существующем стеке. Публичную карту Visit Beloretsk и её embed согласуй с действующей архитектурой, не привязывай к несуществующему адресу.

## Камера и переключение

- После готовности контейнера и итоговой геометрии вычисли bounds только выбранного маршрута и его значимых точек.
- Используй fitBounds/эквивалент, с отступом под панели и мобильную навигацию. Ориентир: 40–64 px, адаптируй к дизайну. Для одиночного маркера — умеренный maxZoom, чтобы не улетать в максимальное приближение.
- Для reference-трека, который шире реального маршрута, не брать bounds всего файла. Сначала сформировать нужную финальную линию.
- Не оставлять весь район из-за того, что запрос построения ещё не завершился: сделай начальное приближение по доступным точкам, затем один раз уточни по готовой линии. Не перебивай ручное движение камеры постоянными автообновлениями.
- При выборе другого варианта синхронно меняются линия, маркеры, подпись, длина и URL. Кнопка «Показать весь маршрут» возвращает его bounds. Назад/вперёд браузера восстанавливает выбранный маршрут.
- В embed показывай выбранный маршрут или варианты этого направления, без всех чужих маршрутов. Изолированный режим не удаляет данные общей карты.
- Если есть обычная и 3D-карта, синхронизируй выбранный routeId и рамку просмотра через одну модель состояния, исключая цикл обновлений.
- При отсутствии полной линии показывай доступные точки, явный статус и ссылку на источник. Не создавай пустой экран или «готовый маршрут» из прямой между точками.

## Отображение данных

Для точек JSON использует lat/lon, GeoJSON использует [lon,lat]. Сохраняй sourceUrl, geometrySource, дату проверки, revision, buildStatus. Принятые точки пользователя нельзя тихо сдвигать к другой вершине. Допустимо хранить отдельно snappedPoint и originalPoint с расстоянием смещения.

В маршруте отдели цель похода от фактического финиша: на радиальном финиш совпадает со стартом. Координаты центра деревни в points — ориентиры с precision=not_trailhead; не использовать их автоматически как найденную парковку.

## Что показать по завершении

Внеси изменения в код, выполни уместные проверки и покажи результат на телефоне и компьютере. Проверь прямое открытие маршрута Рассыпной, переключение двух стартов Ялангаса, три вершины Малиновой, разные тропы Иремеля, короткий вариант Краки, режим 3D при наличии, запись без полной геометрии. Проверь отсутствие фиктивных линий и отсутствие новых дублей.

Верни: изменённые файлы, фактический формат ссылки/embed, список реально построенных маршрутов, список оставшихся технических пробелов и краткую проверку. Не пиши, что все маршруты построены, если часть осталась только точками. Не публикуй новые страницы направлений в рамках этой задачи: сначала готовится единая карта и её API подключения. Внедрение на рабочую карту делай в пределах разрешений текущего проекта.
